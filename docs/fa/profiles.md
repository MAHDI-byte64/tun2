# پروفایل‌ها

[English](../profiles.md) · **فارسی**

پروفایل چند مقدار را یک‌جا برای یک نوع کاربرد تنظیم می‌کند. با کلید سطح بالای `profile` انتخابش کنید؛ هر مقدار را باز هم می‌شود در `[tunnel.mux]`، `[tunnel.kcp]` یا `[tuning]` دستی عوض کرد.

```toml
profile = "ultraspeed"            # balanced (default) | ultraspeed | gaming
```

| | `balanced` (پیش‌فرض) | `ultraspeed` | `gaming` |
|---|---|---|---|
| برای | بیشتر کاربردها | انتقال حجیم، بیشترین سرعت | بازی، صدا، UDP زنده |
| بافر relay | 64 KiB | 256 KiB | 16 KiB |
| پنجرهٔ stream در mux | 256 KiB | 1 MiB | 64 KiB |
| اتصال‌های mux | 4 | 8 | 2 |
| ادغام نوشتن در mux | روشن | روشن | خاموش |
| Keepalive / ping | 30 s | 30 s | 10 s |
| KCP FEC | خاموش | خاموش | 10 / 3 |
| پنجرهٔ ارسال KCP (تطبیقی تا) | 1024 (4096) بسته | 1024 (16384) | 512 (2048) |
| بافر سوکت UDP | 1 MiB | 4 MiB | 1 MiB |
| صف جریان UDP | 128 بسته | 512 بسته | 64 بسته |
| بافر نشست UDP | 256 KiB | 1 MiB | 128 KiB |

## `balanced`

حد وسط برای ترافیک مخلوط. یک stream در هر رفت‌وبرگشت حداکثر ۲۵۶ KiB جابه‌جا می‌کند، روی مسیر ۶۰ms حدود ۲۵ تا ۳۰ Mbit/s؛ برای بیشتر `tunnel.mux.stream_window` را بالا ببرید یا `ultraspeed` بگذارید.

## `ultraspeed`

بیشترین سرعت برای هر اتصال: پنجرهٔ stream چهار برابر، اتصال‌ها دو برابر و بافرها همه‌جا بزرگ‌تر. برای هر stream فعال حافظه می‌خواهد (هرکدام تا اندازهٔ پنجره) و پنجره‌های بزرگ می‌گذارند انتقال حجیم صف‌های مسیر را پر کند، که برای هر چیز دیگری که از همان مسیر می‌رود تأخیر می‌آورد.

برای بیشترین سرعت، ترنسپورت را هم متناسب با مسیر انتخاب کنید:

- **مسیر تمیز:** `tcp` یا `tcpmux`، با `encryption = "auto"` (روی CPUهای دارای دستورهای AES، AES-256-GCM).
- **مسیر پراتلاف:** `kcp`، یا `quic` با `congestion = "bbr"`؛ ترنسپورت‌های مبتنی بر TCP زیر اتلاف تصادفی فرو می‌ریزند.
- **فراتر از پیش‌فرض‌ها:** `tunnel.mux.stream_window` تا ۱۶ MiB بالا می‌رود. یک stream تقریباً به پهنای‌باند × RTT نیاز دارد: ۱۰۰ Mbit/s با ۱۰۰ms برابر ۱٫۲۵ MB است.

`throughput`، نام قدیمی آن پیش از v0.5.1، هنوز پذیرفته می‌شود.

## `gaming`

تأخیر کم و یکنواخت برای بسته‌های کوچک:

- بافرها و پنجره‌های کوچک: یک دانلود نمی‌تواند مسیر را پر کند، پس بسته‌های بازی پشت آن صف نمی‌کشند.
- بدون ادغام نوشتن: هر frame فوراً می‌رود.
- ping هر ۱۰ ثانیه.
- روی `kcp`، FEC با ۱۰ / ۳: بیشتر بسته‌های گم‌شده در یک بازهٔ KCP بازسازی می‌شوند، نه اینکه گم شوند.

روی هر دو سمت استفاده‌اش کنید (FEC را هر سمتِ فرستنده تعیین می‌کند). برای duplication و اندازه‌گیری‌ها [فوروارد UDP و بازی](udp-and-games.md) را ببینید.

## دستی عوض کردن مقدارها

```toml
profile = "gaming"

[tunnel.mux]
stream_window = 262144            # a larger window than gaming's 64 KiB

[tunnel.kcp]
fec_data = 0                      # FEC off despite the gaming profile
fec_parity = 0

[tuning]
keepalive_secs = 20
```

`kariz check` مقدارهای مؤثر را بعد از پروفایل و دستکاری‌ها چاپ می‌کند.
